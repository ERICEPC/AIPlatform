# Raccoon X 本地 Codex Connector

这个连接器只在员工自己的电脑上运行，个人助手网页通过云端 API 将任务转发到这里。连接器调用本机 `codex exec`，因此本地 Codex 的模型、Skill、MCP、项目目录和审批策略都由本机 Codex 配置决定。

```bash
cd deployment/codex-connector
npm ci
CODEX_CONNECTOR_TOKEN='请生成一个随机长 token' \
CODEX_ALLOWED_ROOTS="/" \
CODEX_WORKDIR="$HOME/Work_Project/RaccoonX" \
npm start
```

默认监听 `127.0.0.1:8788`，不会直接暴露到公网。云端要访问本机时，应使用企业内网反向隧道或一个出站轮询 Relay；不要把端口直接映射到公网。

本机全目录工作区：上述 `CODEX_ALLOWED_ROOTS=/` 允许通过系统文件夹选择器选择本机任意目录；仍受 macOS 文件访问权限控制。`CODEX_WORKDIR` 仅作为未指定工作区时的默认目录。需要限制目录的其他部署可自行设置 `CODEX_ALLOWED_ROOTS`，目录边界校验仍然生效。

## 本地能力配置

`capabilities.mjs` 在每次新任务和续聊时注入配置，不修改 `~/.codex/config.toml`：

- 继承本机已安装、启用且已授权的 Codex Skills、插件和 MCP；文件、代码、测试、文档、PPT、表格、PDF 等按实际任务加载。
- 开启实时搜索，以及工作区沙箱内的网络访问；仍使用 `workspace-write`，不启用全盘写入或跳过系统权限。
- 开启图片理解/生成和原生 Computer Use 入口；具体服务、账号与系统权限仍需有效。开启不等于每项工具均完成了实测。
- 安装锁定版本的 Playwright MCP（依赖见 package-lock.json）。`raccoon_browser` 使用独立 Chrome，会话隔离，支持读取网页、点击、输入、截图；不会带入日常浏览器登录态。此本地 MCP 在后台任务中预先授权工具调用，实际业务动作仍必须来自用户任务；不是取消平台发布审批。
- 原生 CUA 用于本机应用。桌面客户端的浏览器桥接凭据是会话专属的，不会传给后台小助手。无独立浏览器桥接时使用 `raccoon_browser`。
- 保留 `agent-cli-broker.mjs` 的当前账号/空间授权、草稿、发布和审批规则。

`GET /health`（需要连接器令牌）返回 `configuredCapabilities`，仅表示配置，不是授权或连通性证明。外部应用登录、系统屏幕/辅助功能授权、图像生成额度等必须实际调用确认。电脑需要保持开机，桌面工具还依赖本机应用服务正常运行。

多账号部署须另行实现账号与设备的绑定；此连接器操作的是它所在的电脑，不能因为平台切换了账号就认为已切换到另一台电脑。不要把当前聊天的桥接身份当成可分发的服务凭据。

回退：移除 server.mjs 对 capabilities.mjs 的导入、提示词与启动参数注入，恢复原先子进程环境并重启；本次没有改动全局 Codex 配置或云端业务数据。

## 本机应用的交互授权（2026-11-09）

启动时设置 `CODEX_CONNECTOR_TRANSPORT=app-server`，使用双向交互协议；不设置时保留原 `exec` 路径作为回退。连接器 `/run` 的请求和返回格式不变。

- 本机确认页监听 `127.0.0.1:8790`。专用入口写入 `/tmp/raccoonx-local-approval-url`（仅本机用户可读），只供电脑使用者打开，不传给云端或模型。
- 应用工具真正请求授权时，页面显示任务、应用及操作。使用者点击允许或拒绝；连接器将决定返回原请求，继续当前任务，不新建一条审批任务冒充授权。
- 当前支持不含输入字段的 MCP 确认表单，以及命令/文件变更的单次确认。对低风险应用访问可选择“允许本次任务使用此应用”，授权只匹配当前线程、当前轮次及应用 ID，任务结束清除；其他应用和其他类型操作不会继承。需要额外输入的表单不会自动填充；不支持的请求明确返回错误。
- 两分钟未决定自动拒绝，整个本机任务最多五分钟；进程结束取消剩余请求。应用任务串行执行，避免多个任务争用桌面。
- 不修改系统辅助功能、屏幕录制或应用安全设置；这些权限仍需使用者正常授予。浏览器和本机应用均不能借用其他会话凭据。
- 确认页使用独立随机令牌、Host/Origin 校验及禁止嵌入策略；拒绝未认证、跨站及重复提交。没有自动批准所有应用的开关。

检查：`node --test deployment/codex-connector/local-approvals.test.mjs`。
该授权桥接的协议依据：[App Server approvals / MCP elicitation](https://learn.chatgpt.com/docs/app-server)。

### 实机验收结果

2026-11-09 已从个人助手真实对话续接同一会话，通过本机确认页授权后，由原生应用工具操作 PowerPoint 填写标题/副标题、打开保存界面并保存到工作区。最终续接执行 67 秒，回传 PPTX；独立读取 PPTX 验证为一页，标题和副标题正确。截图及校验记录位于 `verification/desktop-e2e/`。

此前两轮用于排查单次授权重复弹窗，已停止；最终版本按应用与任务边界复用明确授权，不自动批准其他操作。Office `~$` 临时锁文件已从交付扫描中排除，原文件仍由 Office 自己管理。当前在本机运行；未将这项本机服务部署到云端，也未宣称所有本地应用均已验收。

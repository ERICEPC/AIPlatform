# Raccoon X 前端 v4 变更说明（2026-11-08）

基线：用户上传的 `RaccoonX-frontend-20261108.zip`（本仓库第一个提交原样保存）。依据：《Raccoon X 企业 AI 中台建设规划｜功能与技术路径》、会议纪要「企业 AI 中台演示准备与方案对齐会」、《Raccoon X 智能体中台｜产品介绍与使用指南》（2026-11-08），以及用户当日的几轮要求。

## 1. 整体架构：一套前端，两个区域，三类角色

| 角色 | 登录后看到 | 能做什么 |
| --- | --- | --- |
| 开发者（与 xBuddy 同一身份） | 开发者工作台 | 用个人权限搭建自己的工作流与智能体；获得组织授权后为组织搭建专家智能体团队；查看和配置自己做的智能体、Buddy 应用、工程与数据资源；发布需提交审批 |
| 普通管理员（按部门 / 业务 / 工作流授权） | 开发者工作台 ＋ 管理后台 | 审批范围内的发布；为业务配置资源（数据库 schema、知识库空间、模型额度、可调用的 xBuddy）开放给更多人；技术栈组件只读 |
| 超级管理员 | 开发者工作台 ＋ 管理后台（全部） | 全部权限：AI 技术栈组件连接配置、测试与导出，应用接入，任命管理员 |

X 平台最主要的使用方式是被业务应用调用：SalesBuddy 主要用智能体与知识库；ProjectBuddy 用整套技术栈给用户做开发（例如开发 SalesBuddy 这样的业务应用）。开发者在 ProjectBuddy 里能做的配置，更详细的状态与监控在 X 平台用户端查看。

## 2. 视觉：企业专业软件风格

- 主色由青柠绿改为企业蓝 `#2563EB`（悬停 `#1D4ED8`），去掉深色模式里偏绿的底色；默认浅色。
- 去掉毛玻璃、霓虹流光、背景光斑、数字暗纹、颗粒与登录页 3D 星座；卡片 8–10px 圆角、按钮 6px、标题 20–24px。
- 外框改为顶栏 ＋ 左侧导航 ＋ 内容区；新增通用版式 `src/components/console.tsx`（页面头、页签、卡片、指标行、设置行、按字段渲染的配置表单）。
- 发布出去的智能体 Web 应用主题 `public/webapp-theme.css` 同步改蓝。
- 设计包 `design-kit` 的颜色说明同步更新。

## 3. 新增与改动的页面

开发者工作台：

- **个人助手**：演示模式可显示 Router 执行步骤；配置页「记忆与优化」链接到优化中心。
- **待我确认**（重做）：按 9.5 设计回答五个问题，支持确认、修改后确认、补充、转交、退回；确认与执行状态分开。
- **个人智能体优化**（新增）：总览 · 任务路由（个人 Router 规则、策略、试运行）· 记忆（个人 · 团队 · 待我审查 · 体检与优化 · 记忆策略）· 技能 · 专家智能体 · 桌面与云端。
- **工作流团队**（原 Agent Teams，恢复显示）：新增「Leader 记忆与技能」（团队 Router · 团队记忆 · Leader 技能 · 复盘与优化 · 记忆配置；Leader 可以是个人或组织专家智能体；Leader 不读成员私人记忆）和「对话窗口」（执行过程按聊天方式展开）；「让我的助理配置」按描述起草团队；发布改为提交审批。
- **智能体**：发布改为「提交发布审批」（可见范围、测试结果）；演示模式下企服目录恢复显示。
- **我的发布**（新增）：发布申请与审批结果；「把我的助手复制为专家智能体」。
- **技术栈**（新增）：平台 MCP · 数据库与存储 · 模型与额度 · Buddy 加速器 · 脚手架 · 调用与监控；每页显示依赖组件的只读状态。
- **平台 MCP**（新增，一切皆 MCP）：十个平台 MCP 服务与工具目录（风险分级）、试调用（写入与对外只预演）、按调用方生成客户端配置（个人助理 · 编排引擎 · 各个 xBuddy）。

管理后台（新增）：概览 · 发布审批 · 组织与成员 · 管理员与权限 · 业务空间 · 应用接入（xBuddy）· AI 技术栈组件（连接配置、测试、导出）· 审计日志。

组织与权限参考飞书管理后台的逻辑：

- **组织与成员**：成员与部门从飞书或统一身份同步（通讯录同步：字段映射、定时与立即同步、同步日志）；**用户组**分静态与按规则动态，用于可用范围、审批人与记忆审查人。
- **管理员与权限**：管理员 ＝ 成员 ＋ 管理员角色 ＋ 管理范围（部门 / 业务 / 工作流）；管理员角色是权限项的集合，预置角色（超级管理员 · 业务管理员 · 部门管理员 · 工作流管理员 · 审计员）＋ 自定义角色；权限矩阵按对象列出三类角色能做什么。
- **发布审批**：通过时可按部门、用户组设置可用范围，只有范围内的人看得到、用得到。
- **应用接入**：每个 xBuddy 列出开放能力对应的 MCP 服务、端点与工具。

登录（重做）：账号登录、企业统一身份（飞书、xBuddy 统一身份）、演示账号（开发者 · 普通管理员 · 超级管理员）。

## 4. 接口与配置

- 新增接口见 `docs/api/v4-新增接口.md`（含平台 MCP、用户组、通讯录同步、管理员角色）；均有 mock，字段与正式接口一致。
- 运行时配置 `public/rx-config.js`：部署后改后端地址不用重新构建；见 `docs/后端连接配置.md`。
- 个人助手配置接口在 mock 模式下提供演示数据（live 模式不变）。

## 5. 未改动与边界

- 知识库、Skills、MCP、智能体配置、智能体协同等原有模块的功能与接口不变，只随全局样式变化。
- 新页面为前端与接口层，后端接口需按清单实现；演示数据不代表真实业务记录。
- `legacy-reference/` 为历史离线原型，保持原样。

## 6. 与 ProjectBuddy 一体（2026-11-08 下午）

- 脚手架：模板列表标出「ProjectBuddy 可用」；模板详情新增「发布到 ProjectBuddy」开关（`PATCH /stack/scaffold/templates/{id}`）。模板只在 X 平台维护一份，ProjectBuddy 的普通开发者直接用它新建 Buddy 应用。
- 顶栏新增「ProjectBuddy」免登录入口（`rx-config.js` 的 `projectbuddyUrl`）。
- 应用接入：ProjectBuddy 的说明改为「与 X 平台账户体系一体」。

## 7. v4.1（2026-11-08 晚）

- 「待我核对」改名「待我确认」：导航、页面标题与空状态、命令面板、个人 Router 规则目标、记忆体检建议、平台 MCP（`rx-inbox` 服务名「待我确认」，工具「提交确认事项」「查询确认结果」）、接口注释与文档。路由与接口路径不变（`#review`、`/inbox`）。
- 带颜色的模块标识：`src/components/page-mark.tsx`（`ModuleMark`、`PageMarkContext`）；`shell.tsx` 每个导航项配一个颜色；`App.tsx` 按路由向页面提供当前模块标识，`PageHeader` 在标题前显示。

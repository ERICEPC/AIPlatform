# 后端连接配置（2026-11-08）

前端要连上 X 平台后端，分两层配置：

1. **前端 → X 平台后端**：前端调用哪个接口地址（本文第 1 节）。
2. **X 平台后端 → 各个 AI 技术栈组件**：数据库、向量库、缓存、对象存储、模型网关、编排引擎、个人助手服务、知识库、记忆服务、MCP 网关、Buddy 加速器、脚手架、统一身份等（第 2 节）。由超级管理员在管理后台「AI 技术栈组件」填写、测试并导出，再写入后端部署环境。

## 1. 前端连接后端

部署后直接改 `dist/rx-config.js`，不用重新构建：

```js
window.RX_CONFIG = {
  apiMode: 'live',                               // 'live' 连接后端；'mock' 演示数据
  apiBase: '/console/api',                       // 控制台接口前缀
  kbBridge: '/console/api/knowledge-bridge',     // 知识库代理前缀
  kbAppUrl: 'https://kb.example.internal/app',   // 完整知识库应用（可选）
}
```

- 值为 `null` 时使用构建时的环境变量（`.env.production`：`VITE_API_MODE`、`VITE_API_BASE`、`VITE_KB_BRIDGE`、`VITE_KB_APP_URL`）。
- 建议同域反向代理：浏览器访问 `https://x.example.com/new-ui/`，Nginx 把 `/console/api/` 转发到 X 平台后端。接口使用 Cookie 会话与 `X-CSRF-Token`，跨域部署需要后端另配 CORS 与 Cookie 策略。
- 部署子路径：默认 `/new-ui/`；部署到根目录时用 `VITE_BASE=/ pnpm build` 重新构建（见原 README）。
- 离线单文件 `RaccoonX-新前端.html` 固定使用演示数据，不读取 `rx-config.js`。

## 2. 后端连接各个 AI 技术栈组件

| 分类 | 组件 | 用途 | 开发者在用户端 |
| --- | --- | --- | --- |
| 数据与存储 | 业务数据库（PostgreSQL） | 平台元数据、业务空间 schema、工作流与发布记录 | 「数据库与存储」查看分配的 schema 与用量 |
| | 向量数据库（Milvus / pgvector） | 知识库与记忆的向量检索 | 查看向量集合与索引状态 |
| | 缓存与热记忆（Redis） | 会话上下文、短期记忆、任务队列、限流 | 无需配置 |
| | 对象存储（S3 兼容） | 上传文件、交付物、知识库原文 | 查看目录与用量 |
| | 全文检索（OpenSearch） | 关键词召回、审计检索 | 无需配置 |
| 模型与网关 | 模型网关（MaaS 平台，OpenAI 兼容） | 统一接入模型、按任务选模型、计量到人和任务 | 「模型与额度」 |
| | 向量化与重排序 | 知识库与记忆 | 无需配置 |
| 智能体运行 | 编排引擎（X 平台核心） | 智能体、工作流团队、版本与运行记录 | 「智能体」「工作流团队」 |
| | 个人助手服务（DeepSeek Harness） | 个人智能体：Router、工具与专家调用、桌面与云端协同 | 「个人智能体优化」 |
| | 桌面连接器网关 | 本地连接器注册、心跳、命令下发 | 「桌面与云端」 |
| | 代码执行沙箱 | Skill 脚本与代码执行 | 无需配置 |
| 知识与记忆 | 知识库服务（多模态 RAG） | 入库、解析、带出处的问答与权限 | 「知识库」 |
| | 记忆服务 | 个人、团队、Leader 记忆；候选、确认、审查 | 「记忆」「Leader 记忆与技能」 |
| | 文档解析与 OCR | 解析与转写 | 无需配置 |
| 工具与集成 | MCP 网关 | 远程 MCP 服务接入、授权、审计 | 「MCP 与工具」 |
| | 插件市场 | 插件安装来源（默认用内网镜像） | 插件市场 |
| | 消息渠道 | 飞书、企业微信、钉钉 | 智能体「访问」 |
| 开发套件 | Buddy 加速器 | xBuddies 框架层与平台 SDK | 「Buddy 加速器」 |
| | 脚手架 | create-buddy 与模板库 | 「脚手架」 |
| 身份与安全 | 统一身份（OIDC · 飞书 · xBuddy） | 开发者、管理员与 xBuddy 用户同一身份 | 无需配置 |
| | 密钥管理（KMS） | 模型密钥、渠道凭据加密 | 无需配置 |
| 观测 | 日志与监控（OpenTelemetry） | 调用链、指标、日志 | 「调用与监控」 |

操作：超级管理员登录 → 顶栏「管理后台」→「AI 技术栈组件」→ 选组件 → 填写连接 → 「测试连接」（`POST /admin/stack/components/{id}/test`，不保存）→「保存」（`PUT /admin/stack/components/{id}`）→ 页面右上角「导出后端连接配置」得到 `.env` 或 JSON。

导出的变量名格式为 `RX_<组件>_<字段>`，例如：

```env
RX_POSTGRES_HOST=pg-primary.example.internal
RX_POSTGRES_PORT=5432
RX_POSTGRES_PASSWORD=${RX_POSTGRES_PASSWORD}
RX_MODEL_GATEWAY_ENDPOINT=https://maas.example.internal/v1
RX_MODEL_GATEWAY_API_KEY=${RX_MODEL_GATEWAY_API_KEY}
```

密钥只以占位符导出，真实值放在部署环境的密钥管理里；接口返回的密钥字段只给掩码，保存时密钥留空表示不修改。

## 3. 后端需要提供的接口

前端新增或改动的接口见 `docs/api/v4-新增接口.md`。mock 模式下这些接口由 `src/api/mock/*.ts` 模拟，字段与正式接口一致；切到 live 后页面代码不用改。

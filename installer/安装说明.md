# RaccoonX 2026.10.28 安装说明

此包用于全新实例部署，Linux amd64，基于定制 Dify 1.17.0。不要覆盖已有生产实例目录或数据库。

## 准备

- Ubuntu 22.04 / 24.04 x86_64；建议 4 核、16GB 内存、25GB 可用磁盘。
- 安装时需要访问 Docker 镜像仓库和 PyPI。模型、插件及外部工具还需各自服务可达。
- 准备域名或公网 IP，开放所选 HTTPS 端口。默认安装目录 `/opt/raccoon-agent` 必须不存在。
- 本包没有原站点数据或密钥，不带任何模型额度。

## 安装

将压缩包和对应 `.sha256` 文件上传到服务器，同目录执行：

```bash
sha256sum -c RaccoonX-2026.10.28.tar.gz.sha256
tar -xzf RaccoonX-2026.10.28.tar.gz
cd RaccoonX-2026.10.28
sudo bash prepare-ubuntu.sh
sudo bash install.sh --public-url https://你的服务器IP:8443
```

`prepare-ubuntu.sh` 安装必要系统依赖；运行前可先检查脚本。安装会拉取固定摘要基础镜像、构建定制层、生成独立随机密钥、迁移原生数据库和扩展空表，再启动服务。

有正式证书时：

```bash
sudo bash install.sh --public-url https://你的域名 \
  --cert /安全目录/fullchain.pem --key /安全目录/privkey.pem
```

未提供证书时生成含 IP/域名 SAN 的自签证书。将新实例的公开 `runtime/tls/server.crt` 导入客户端信任或换成正式证书；不要通过关闭 TLS 验证解决访问问题。

可选参数：`--install-dir /opt/另一个新目录`、`--bind-address 127.0.0.1`。后者适合已有反向代理或本机验收。

安装失败后先检查原因，仅对同一安装目录、相同地址参数加 `--resume` 恢复。它保留已生成密钥和数据，不是升级程序。不要将本包直接安装到原 Dify/RaccoonX 目录。

## 首次登录

```bash
sudo cat /opt/raccoon-agent/首次登录.txt
```

打开该地址，用生成的初始化口令进入初始化页面，再创建自己的管理员账号。此文件含敏感信息，应私下保存；没有共享 ERIC Team Access 账号。

进入后配置自己的模型供应商、Embedding/Rerank、插件、工具和知识库。消息渠道需要自己的企业微信/钉钉等凭据。既有服务器中的 SalesBuddy、ProjectBuddy、生态渠道账号及应用不会出现在新实例中。

如果管理员需要开启“创建工作空间”，可执行：

```bash
sudo python3 /opt/raccoon-agent/access.py workspace 管理员邮箱
```

此操作只授权新实例中查到的账号。不要直接使用旧服务器的账号 UUID。

## CLI 2.1

客户端在安装包 `cli/` 目录，使用 Python 3，无第三方依赖。

```bash
python3 raccoon.py --workspace 新空间UUID init --server https://你的域名 --profile MyProject
```

然后本人在空间设置的“CLI 授权管理”提交申请，使用生成的 project_id。由空间 Owner 或其委派的管理员审批，再执行：

```bash
python3 raccoon.py auth login --authorization 批准记录UUID
python3 raccoon.py auth whoami
python3 raccoon.py doctor
python3 raccoon.py list
```

本人必须核对浏览器账号、空间和确认码。任何人不能自审；Owner 申请自己的授权时须先将另一位 admin 委派为审批人。最长批准窗口 7 天，不自动续期。

旧 `access.py cli` 白名单方式已停用。CLI 管理授权不等于业务运行 API Key；没有 run/stop 命令。详见 `cli/接口与使用说明.txt`。

## 维护与备份

```bash
sudo bash /opt/raccoon-agent/manage.sh status
sudo bash /opt/raccoon-agent/manage.sh logs
sudo python3 /opt/raccoon-agent/healthcheck.py --wait 120
```

具体支持的维护命令可查看 `manage.sh`。部署目录权限为 0700；`runtime/.env`、TLS 私钥和首次登录文件为 0600。不要把这些文件提交到 Git。

备份需覆盖 PostgreSQL、上传存储、向量库及加密密钥；只有数据库备份不足以恢复加密的模型凭据。此包不包含自动备份/跨版本升级流程。不要在使用原数据的情况下重新生成 SECRET_KEY。

签名文件下载由 API 校验签名、有效期和文件权限，下载路径不依赖浏览器登录；文件签名参数仍须完整。

OKR 服务代码已包含，默认没有任何可用业务 Key 或快照绑定。请按 `OKR说明.txt` 另行完成受控接入，不应把联调能力当成已验收业务服务。

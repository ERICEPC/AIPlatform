## 1. 需求与实现

| # | 需求 | 实现 |
|---|---|---|
| 1 | 申请共享：仅个人 / 部门 / 公共空间（智能体、团队、Skills、MCP） | 统一共享弹窗 `components/resource-visibility.tsx`。仅个人立即生效并撤回审批中的申请；部门＝申请人所在部门，由部门负责人或超管审批；公共空间只有超管能批 |
| 2 | 我的发布 | `pages/my-releases.tsx`：本人全部资源 + 当前范围 + 最近申请状态，审批后同步 |
| 3 | 发布审批页改版 | `pages/admin/approvals.tsx`：通过 / 驳回 / 转审、批准范围、意见在顶部；资源信息内联；去掉「可用范围」标签行 |
| 4 | 审批规则与组织 | 超管 李鹏程 / 周玮 / 叶源；部门负责人可多位、可转审；不能审批自己；至少保留一位超管。组织与成员页：成员与部门 / 部门负责人 / 身份来源 |
| 5 | 业务空间 | `pages/admin/spaces.tsx`：按部门看智能体调用次数、调用人数、各模型 Token、最近调用（7 / 30 天）；去掉原资源配置表单 |
| 6 | 侧边栏与审计 | 去掉「平台」分组，隐藏应用接入和 AI 技术栈（路由保留，仅超管可直达）；审计只记人的操作，列为 时间 / 操作人 / 对象 / 内容 / 部门 / 结果，可按操作人、类别、部门、结果、时间、关键字筛选 |
| — | 统一身份 | OIDC 授权码 + PKCE（BFF）；已有账号「登录后绑定」，不按邮箱合并；租户白名单 |

```

PARTNER_AUTH_CLIENT_ID=<Auth 提供>
PARTNER_AUTH_CLIENT_SECRET_FILE=<私有密钥文件路径>
PARTNER_AUTH_REDIRECT_URI=https://10.151.113.125:21190/console/api/auth/partner/callback
PARTNER_AUTH_WORKSPACE_ID=<平台工作空间 ID>
PARTNER_AUTH_ALLOWED_TENANTS=<sensetime-CNI生态渠道在 Auth 中的 tenant_id>
```

- 接口：`GET /console/api/auth/partner/status`、`GET /console/api/auth/partner/login[?bind=1]`、`GET /console/api/auth/partner/callback`；未配置时登录返回 503「统一身份未配置」。
- 新工作空间若还没有超管，需在 `rx_admin_assignments` 手动写入第一位超管（role-super），其余在页面设置。

## 5. 首次使用（盒子环境）

1. 李鹏程、周玮、叶源：先用原账号密码登录 → 左下角账号菜单「绑定企业统一身份」→ 跳转 Auth 登录后回到平台，绑定完成。
2. 之后在登录页「企业统一身份」直接登录。
3. 新同事首次用统一身份登录会自动建立成员账号（未分配部门），由超管在「组织与成员」分配部门。
4. 若提示「该邮箱已有平台账号」，说明此人已有账号但未绑定，按第 1 步操作。

## 6. 验收路径（演示模式或盒子环境均可）

1. 成员（演示：周莹）在「智能体」点「申请共享」→ 选「部门」提交 → 「我的发布」显示「审批中」。
2. 部门负责人（演示：蒋磊）→ 管理后台「发布审批」→ 只看到本部门申请 → 通过，或填意见后「转审超级管理员」。
3. 超管（演示：李鹏程）→ 看到全部申请（含转审、公共空间）→ 公共空间申请可收窄为部门后通过。
4. 回到成员 → 「我的发布」状态已同步。
5. 超管查看「组织与成员」「管理员与权限」「业务空间」「审计日志」。

本地演示模式（不需要后端）：

```bash
cd frontend-20261112-preview
pnpm install --frozen-lockfile
pnpm exec vite --host 127.0.0.1 --port 5184
```

打开 http://127.0.0.1:5184/new-ui/#login →「演示账号」；左下角账号菜单可切换周莹（成员）、蒋磊（北区东区负责人）、李鹏程 / 叶源（超管）。

# 智能体开发治理改版 · 统一设计规格（YUAN）

适用三处代码，行为必须一致：
- 演示前端：`AIPlatform-yuan/frontend-20261112-preview`（mock 模式 + live 模式）
- 演示旧后端：`AIPlatform-yuan/installer/runtime/build/api/code`（Flask/Dify，`controllers/console/agent/governance.py` 等）
- 生产：RaccoonX 分支 `frontend/src`（live 页面 Platform*）+ `services/raccoonx`（FastAPI + PostgreSQL 迁移）

所有界面文字为简体中文。不出现 "Dify" 字样。

## 0. 角色

| 角色 | 谁 | 能做什么 |
|---|---|---|
| 超级管理员 | 李鹏程、周玮、叶源（三人都是） | 全部：审批部门与公共空间申请、配置部门与部门负责人、维护成员所属部门、看全量组织树/业务空间/审计 |
| 部门负责人（部门老大） | 由超级管理员给部门指定，一个部门可有多位 | 审批本部门（含下级部门）成员的「部门」申请、把申请转审给超管、看本部门（含下级）业务空间和审计；组织树只读看本部门子树 |
| 普通成员 | 其他人 | 开发、申请共享、看自己的「我的发布」 |

- 任何人不能审批自己提交的申请（超管也不行，交给另一位超管）。部门负责人遇到自己的申请只能转审。
- 至少保留一位超级管理员。

## 1. 共享范围（申请共享）

资源类型：智能体 agent、智能体团队 team、Skills skill、MCP 与工具 mcp。四类在各自列表/详情上的「申请共享」按钮行为一致。

点击「申请共享」弹出下拉/弹窗，三个选项：
1. **仅个人** `private`：只有自己可见。**不需要审批，立即生效**。若当前是部门/公共空间，则立即收回共享；若有审批中的申请，自动撤回。
2. **部门** `department`：共享到**申请人所在部门**（成员只属于一个部门；未分配部门时此项禁用并提示「请联系超级管理员分配部门」）。提交后进入审批，由该部门负责人或超级管理员审批。
3. **公共空间** `public`：当前租户全量账号可见。提交后进入审批，**只有超级管理员能审批**。

- 申请时填「申请说明」（选填，最多 500 字）。
- 审批中：资源当前可见范围**不变**；按钮显示「审批中 · 部门/公共空间」，可撤回。
- 通过：资源可见范围变为批准的范围。审批人可把「公共空间」收窄为「部门」，不能放大。
- 驳回：资源可见范围不变，申请状态为「已驳回」，申请人看到驳回意见。驳回必须填意见。
- 已共享资源再次申请更大范围（部门→公共空间）走同样审批；改小（→仅个人）立即生效。
- 草稿/未发布资源不能申请部门或公共空间（保留原有校验：智能体需已发布、团队需已发布、MCP 需已授权）。
- 每个资源同一时间最多一条审批中的申请。

按钮文案：未共享「申请共享」；审批中「审批中」；已共享显示当前范围「部门可见 / 公共空间」并可点开再改。

## 2. 我的发布

侧边栏「智能体开发」分组里的「我的发布」。展示**当前账号自己创建的全部** agent / team / skill / mcp，不论范围（仅个人、部门、公共空间都列出）。

- 顶部分类 Tab：全部 / 智能体 / 智能体团队 / Skills / MCP与工具（带数量）。
- 指标行：仅个人、部门、公共空间、审批中 的数量。
- 筛选：可见范围（全部/仅个人/部门/公共空间）、审批状态（全部/无需审批/审批中/已通过/已驳回/已撤回）。
- 每行：资源名、类型标签、**当前可见范围**、**最近一次申请的状态**（审批中显示「申请 部门/公共空间 · 审批中 · 审批人：xx部门负责人/超级管理员」；已转审显示「已转审超级管理员」）、提交时间、审批意见按钮、操作：修改共享范围（同第 1 节弹窗）、撤回（审批中时）、查看资源。
- **状态联动**：数据来自服务端同一张申请表 + 资源可见范围表；管理端审批后，申请人刷新/重新进入「我的发布」即看到新状态（live 模式轮询或进入页面重新拉取；mock 模式共享同一份内存数据，切换演示账号即可看到）。

## 3. 发布审批（管理后台）

路由 `#admin/approvals[/<id>]`。左侧申请列表保留（搜索、类型筛选、待审批/已处理 Tab）。右侧详情重新布局，目标：1440×900 屏幕内**不上下滚动**即可看到全部关键信息并操作。

右侧从上到下：
1. **操作栏（固定在顶部，sticky）**：资源名 + 版本 + 类型标签 + 状态；右侧按钮：`通过`（主按钮）`驳回` `转审超级管理员`（仅部门负责人且申请为部门范围时显示）。下面一行紧凑表单：批准范围（下拉：部门/公共空间，只能收窄）+ 意见输入（单行，驳回/转审时必填，placeholder「驳回或转审时必填，申请人可见」）。已处理的申请此处显示结果、审批人、意见、时间。
2. **申请信息条**（一行 KV，6 项）：申请人、所属部门、申请范围、当前范围、提交时间、申请编号。
3. **资源信息前置（两列网格，不跳转）**：
   - 左列「资源概要」：描述；智能体：模型、系统提示词摘要（前 200 字，可展开）、工具/Skills/知识库列表；团队：负责人 + 成员智能体列表；Skill：文件列表 + SKILL.md 摘要；MCP：服务地址（脱敏）、工具列表、授权状态。
   - 右列「发布前检查」（✓/! 列表）、「资源依赖」、「版本变化」，三块紧凑排列。
   - 保留一个次要文字链接「在新标签页打开资源」，不是必须操作。
4. **审批路径**：小时间线：提交 → （转审）→ 审批结果，显示人名和时间。

删除原「可用范围」部门/用户组标签行。

审批可见性：
- 超级管理员：看到全部待审批（部门 + 公共空间 + 已转审）。
- 部门负责人：只看到申请人属于其负责部门（含下级）且范围为「部门」、未被转审的申请；已转审的出现在其「已处理」里，状态「已转审」。
- 转审：部门负责人填写意见后把申请转给超级管理员；申请 `assignee` 从 `dept_head` 变为 `super_admin`，记录转审人和时间；部门负责人不能再审批它。

## 4. 组织与成员（统一身份 Auth + 平台内维护部门）

- 账号与登录来自统一身份 Auth（生产 issuer `https://partner.sensetime.com/auth`，OIDC 授权码 + PKCE，BFF 模式）。登录页「企业统一身份」入口跳转 Auth；首次登录按 `(issuer, tenant_id, sub)` 自动建立平台成员（未分配部门）。账号密码登录保留为开发/演示入口。
- Auth 不提供部门树，**部门树、成员所属部门、部门负责人在平台内维护**（超级管理员操作），预留后续从 Auth `organization_units` 同步。
- 页面 Tab：`成员与部门` `部门负责人` `身份来源`（去掉「用户组」「通讯录同步」）。
  - 成员与部门：左侧部门树（超管可新建、重命名、移动、删除空部门），右侧成员表（成员、部门/岗位、角色：超级管理员/部门负责人/成员、最近登录）。超管可修改成员所属部门。去掉「常用 xBuddy」列。
  - 部门负责人：每个部门一行，显示负责人；超管可设置/移除负责人（从该部门及上级部门成员中选）。
  - 身份来源：显示统一身份 Auth 的 issuer、登录方式、接入状态（已配置/未配置）、说明「账号来自统一身份，部门在本平台维护」。
- 可见性：超管看全量组织树；部门负责人只读看本部门子树；成员无权访问管理后台。

## 5. 管理员与权限

- Tab：`超级管理员` `部门负责人` `权限矩阵`（去掉自定义「管理员角色」）。
- 超级管理员列表：李鹏程、周玮、叶源；超管可添加/撤销超管（至少保留一位）。
- 部门负责人列表：负责人、部门、任命人、时间；可撤销。
- 权限矩阵：静态表格，行为操作，列为 成员 / 部门负责人 / 超级管理员。

## 6. 业务空间 = 按部门的智能体用量

- 左侧部门列表（超管：全部部门 +「全部」；部门负责人：只有自己负责的部门）。
- 右侧：时间范围切换 7 天 / 30 天；部门汇总卡片：智能体数、调用次数、调用人数、模型 Token 总量。
- 智能体表：智能体、所有者、可见范围、调用次数、调用人数、模型（按模型列出 Token 用量）、Token 合计、最近调用。按调用次数降序。
- 归属规则：智能体属于其**所有者所在部门**。
- 去掉原「为业务配置」资源配置表单和数据库/存储卡片。

## 7. 侧边栏与审计日志

- 管理后台侧边栏：去掉「平台」分组标题；隐藏「应用接入（xBuddy）」「AI 技术栈组件」（路由也不再出现在导航与命令面板中）；「审计日志」并入管理后台主分组末尾。
- 审计日志只记录**人的操作**，不记录应用调用、智能体运行（智能体运行日志留在智能体详情页的日志 Tab）。
- 列：时间 | 操作人（只显示人名，不显示角色，不出现应用名）| 对象（被操作的资源名，如「客户拜访复盘助手」或成员名/部门名）| 内容（类别 + 简述，如「发布申请 · 申请共享到公共空间」）| 部门 | 结果。
- 内容类别：`发布申请`（提交、撤回、改为仅个人）、`审批处理`（通过、驳回、转审）、`权限变更`（任命/撤销超管、设置/移除部门负责人）、`组织变更`（部门新建/重命名/移动/删除、成员调部门）、`技术栈配置`（技术栈组件配置修改，保留类别）、`登录`（登录成功/失败，可选）。
- 筛选：操作人（下拉，人名）、内容类别（下拉）、部门（下拉，超管可见）、结果（全部/成功/已拒绝/失败）、时间（近 7 天/30 天/全部）、关键字（对象名）。
- 范围：超管看全量；部门负责人看本部门（含下级）相关记录（操作人属于该部门或对象部门属于该部门）。
